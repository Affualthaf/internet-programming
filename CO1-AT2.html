Student Complaint Portal

The Student Complaint Portal allows students to submit complaints related to academics, hostel, transport, library, and other college services.

Question 1 : HTTP Response Analysis

HTTP Response Header

HTTP/1.1 200 OK
Date: Mon, 01 Apr 2026 10:00:00 GMT
Content-Type: text/html
Content-Length: -150
Connection: keep-alive
1. Incorrect Field
  • Content-Length: -150 is invalid because Content-Length cannot be negative.
2. Impact

When the Complaint Portal sends the confirmation page after a complaint is submitted, the browser expects the number of bytes mentioned in Content-Length. Since the value is negative, the browser may reject the response or fail to display the page correctly.

3. Status Code Analysis

Status code 200 OK indicates success. However, because the header contains an invalid field, the response is not completely correct.

4. Correct Header 
HTTP/1.1 200 OK
Date: Mon, 01 Apr 2026 10:00:00 GMT
Content-Type: text/html
Content-Length: 150
Connection: keep-alive

Question 2 : DOM Structure Analysis

<html>
<head>
<title>Complaint Portal</title>
</head>
<body>
<div>
<p>Complaint Submitted
</div>
</body>
</html>
1. Missing Elements
  • The <p> tag is not closed.
2. Browser Interpretation

Modern browsers automatically insert the missing closing tag and render the page correctly.

3. Impact
  • HTML becomes invalid.
  • CSS or JavaScript may behave unexpectedly.
  • Rendering usually still works.
4. Correct Code 
<div>
   <p>Complaint Submitted</p>
</div>

Question 3 : GET vs POST in Login System

Method URL Example Data Visibility Security
GET /login?user=student&pass=1234 Visible in URL Low
POST /login Hidden in Request Body Moderate

Answers

1. Difference
  • GET sends data through the URL.
  • POST sends data inside the request body.
2. Suitable Method

POST is the best choice for the Complaint Portal login because usernames and passwords should not appear in the URL.

3. Risks of GET
  • Password visible in URL.
  • Stored in browser history.
  • Stored in server logs.
  • Can be shared accidentally.
4. Best Practices
  • Use POST method.
  • Use HTTPS.
  • Encrypt passwords.
  • Use session authentication.
  • Validate all inputs.

Question 4 : HTML Code Inspection

<!DOCTYPE html>
<html>
<head>
<title>Complaint Portal</title>
</head>
<body>

<h1>Student Complaint Portal

<p>Submit your complaint

<img src="complaint.jpg">

</body>
</html>
1. Missing Closing Tags
  • </h1>
  • </p>
2. Image Tag Issue

The image should contain an alt attribute. 

<img src="complaint.jpg" alt="Complaint Portal">
3. Browser Behavior
  • Automatically closes missing tags.
  • Still renders the page.
  • HTML is not valid.
4. Correct Version 
<h1>Student Complaint Portal</h1>

<p>Submit your complaint.</p>

<img src="complaint.jpg" alt="Complaint Portal">

Question 5 : Browser-Server Communication Flow

  1. User enters www.studentcomplaintportal.com
  2. DNS converts the domain name into an IP address.
  3. The browser sends an HTTP request to the web server.
  4. The server processes the complaint request.
  5. The server sends an HTTP response.
  6. The browser renders the Complaint Portal webpage.

Where Delays Can Occur

  • DNS lookup
  • Internet connection
  • Server processing
  • Large images
  • JavaScript loading

Role of DNS

DNS converts the website name into an IP address so the browser can locate the Complaint Portal server.

Performance Optimizations

  • DNS caching
  • Browser caching
  • Image optimization
  • Minify CSS and JavaScript
  • Use HTTPS
  • Enable Keep-Alive
  • Use a CDN

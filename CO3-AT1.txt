<section id="q1" class="section">
<div class="section-head head1">
    <h2>01 · Student Registration using Servlet</h2>
    <p>Process student details through HTTP requests and Java Servlet response handling.</p>
</div>
<div class="section-body">

<div class="answer a1">
<h4>Architecture of a Servlet-Based Application</h4>
<p>The browser sends an HTTP request to a web server. The servlet container such as Apache Tomcat maps that request to the appropriate servlet. The servlet reads request parameters, performs processing, optionally communicates with a database, and sends an HTTP response back to the browser.</p>
<div class="flow">
<div class="flow-box f-purple">Browser</div><div class="flow-arrow">→</div>
<div class="flow-box f-pink">Web Server</div><div class="flow-arrow">→</div>
<div class="flow-box f-cyan">Servlet Container</div><div class="flow-arrow">→</div>
<div class="flow-box f-orange">Servlet</div><div class="flow-arrow">→</div>
<div class="flow-box f-blue">Database</div>
</div>
</div>

<div class="answer a1">
<h4>GET and POST Servlet Implementation</h4>
<p><strong>GET</strong> is generally used for retrieving data. Parameters are visible in the URL. <strong>POST</strong> sends the form data in the request body and is preferable for registration data.</p>
<div class="code-title">StudentRegistrationServlet.java</div>
<pre><code>import java.io.*;
import jakarta.servlet.*;
import jakarta.servlet.annotation.WebServlet;
import jakarta.servlet.http.*;

@WebServlet("/student")
public class StudentRegistrationServlet extends HttpServlet {

    protected void doGet(HttpServletRequest request,
                          HttpServletResponse response)
                          throws IOException {

        response.setContentType("text/html");
        PrintWriter out = response.getWriter();

        String name = request.getParameter("name");
        String email = request.getParameter("email");

        out.println("&lt;h2&gt;GET Registration&lt;/h2&gt;");
        out.println("Name: " + name + "&lt;br&gt;");
        out.println("Email: " + email);
    }

    protected void doPost(HttpServletRequest request,
                           HttpServletResponse response)
                           throws IOException {

        response.setContentType("text/html");
        PrintWriter out = response.getWriter();

        String name = request.getParameter("name");
        String email = request.getParameter("email");

        out.println("&lt;h2&gt;Registration Successful&lt;/h2&gt;");
        out.println("Student: " + name + "&lt;br&gt;");
        out.println("Email: " + email);
    }
}</code></pre>
</div>

<div class="answer a1">
<h4>Servlet Life Cycle: init → service → destroy</h4>
<ol>
<li><strong>init():</strong> Executed once when the servlet is created. Initialization resources can be prepared here.</li>
<li><strong>service():</strong> Executed for incoming requests. It dispatches the request to methods such as <code>doGet()</code> and <code>doPost()</code>.</li>
<li><strong>destroy():</strong> Executed once before the servlet is removed, allowing resources to be released.</li>
</ol>
<div class="flow">
<div class="flow-box f-purple">init()</div><div class="flow-arrow">→</div>
<div class="flow-box f-pink">service()</div><div class="flow-arrow">→</div>
<div class="flow-box f-cyan">doGet()/doPost()</div><div class="flow-arrow">→</div>
<div class="flow-box f-orange">destroy()</div>
</div>
</div>

<div class="answer a1">
<h4>Why POST is more appropriate for sensitive data?</h4>
<p>POST is preferable because form parameters are placed in the request body rather than directly in the URL. However, <strong>POST does not encrypt information</strong>. Sensitive information must use HTTPS/TLS, server-side validation and secure authentication. Passwords should never be stored as plain text.</p>
</div>

<section id="q2" class="section">
<div class="section-head head2">
    <h2>02 · Session Management</h2>
    <p>Maintain authentication state across multiple pages using HttpSession and cookies.</p>
</div>
<div class="section-body">

<div class="answer a2">
<h4>How Session Tracking Works</h4>
<p>After successful authentication, the server creates an <code>HttpSession</code>. The servlet container assigns a session identifier, commonly represented by the <code>JSESSIONID</code> cookie. The browser sends that identifier with later requests, allowing the server to find the correct session and its stored attributes.</p>
<div class="flow">
<div class="flow-box f-pink">Login</div><div class="flow-arrow">→</div>
<div class="flow-box f-purple">HttpSession</div><div class="flow-arrow">→</div>
<div class="flow-box f-cyan">JSESSIONID</div><div class="flow-arrow">→</div>
<div class="flow-box f-blue">Next Page</div>
</div>
</div>

<div class="answer a2">
<h4>Login Servlet using HttpSession</h4>
<pre><code>@WebServlet("/login")
public class LoginServlet extends HttpServlet {

    protected void doPost(HttpServletRequest request,
                           HttpServletResponse response)
                           throws IOException {

        String username = request.getParameter("username");
        String password = request.getParameter("password");

        if ("student".equals(username)
                && "1234".equals(password)) {

            HttpSession session = request.getSession();
            session.setAttribute("username", username);

            response.sendRedirect("home");
        } else {
            response.sendRedirect("login.html");
        }
    }
}</code></pre>
</div>

<div class="answer a2">
<h4>Checking Session on Another Page</h4>
<pre><code>HttpSession session = request.getSession(false);

if (session != null &&
    session.getAttribute("username") != null) {

    String user =
        (String) session.getAttribute("username");

    response.getWriter()
            .println("Welcome " + user);
} else {
    response.sendRedirect("login.html");
}</code></pre>
</div>

<div class="answer a2">
<h4>Session-Based Tracking vs Cookies</h4>
<div class="table-wrap">
<table>
<tr><th>Feature</th><th>HttpSession</th><th>Cookies</th></tr>
<tr><td>Storage</td><td>Application state is stored on the server.</td><td>Cookie data is stored in the browser.</td></tr>
<tr><td>Typical use</td><td>Login state, cart, user information.</td><td>Preferences, identifiers and session IDs.</td></tr>
<tr><td>Security</td><td>Useful for server-side session state.</td><td>Client can inspect cookie values.</td></tr>
<tr><td>Size</td><td>Not limited like a cookie because state is server-side.</td><td>Small browser storage.</td></tr>
<tr><td>Relationship</td><td>Can use a cookie to carry the session ID.</td><td>Can contain the JSESSIONID.</td></tr>
</table>
</div>
</div>

<div class="answer a2">
<h4>Logout using Session Invalidation</h4>
<pre><code>HttpSession session =
    request.getSession(false);

if (session != null) {
    session.invalidate();
}

response.sendRedirect("login.html");</code></pre>
</div>

<section id="q3" class="section">
<div class="section-head head3">
    <h2>03 · JDBC Product Management</h2>
    <p>Connect a Java web application to a database, insert products and retrieve records.</p>
</div>
<div class="section-body">

<div class="answer a3">
<h4>JDBC Architecture</h4>
<p>JDBC (Java Database Connectivity) is a Java API that provides a standard way to connect Java programs to relational databases and execute SQL statements.</p>
<div class="flow product-flow">
<div class="flow-box f-blue">Java Web App</div><div class="flow-arrow">→</div>
<div class="flow-box f-cyan">JDBC API</div><div class="flow-arrow">→</div>
<div class="flow-box f-purple">JDBC Driver</div><div class="flow-arrow">→</div>
<div class="flow-box f-orange">MySQL</div>
</div>
</div>

<div class="answer a3">
<h4>Steps in Database Connectivity</h4>
<ol>
<li>Import JDBC classes.</li>
<li>Load/register the database driver when required.</li>
<li>Establish a connection using <code>DriverManager</code>.</li>
<li>Create a <code>PreparedStatement</code>.</li>
<li>Execute INSERT, UPDATE, DELETE or SELECT.</li>
<li>Process the <code>ResultSet</code> for SELECT operations.</li>
<li>Close resources with try-with-resources.</li>
<li>Handle <code>SQLException</code>.</li>
</ol>
</div>

<div class="answer a3">
<h4>Database Table</h4>
<pre><code>CREATE DATABASE ecommerce;

USE ecommerce;

CREATE TABLE products (
    id INT PRIMARY KEY AUTO_INCREMENT,
    name VARCHAR(100) NOT NULL,
    price DECIMAL(10,2) NOT NULL,
    quantity INT NOT NULL
);</code></pre>
</div>

<div class="answer a3">
<h4>Insert Product using PreparedStatement</h4>
<pre><code>public void insertProduct(String name,
                           double price,
                           int quantity) {

    String sql =
        "INSERT INTO products(name, price, quantity) " +
        "VALUES (?, ?, ?)";

    try (Connection con =
            DriverManager.getConnection(
                URL, USER, PASSWORD);
         PreparedStatement ps =
            con.prepareStatement(sql)) {

        ps.setString(1, name);
        ps.setDouble(2, price);
        ps.setInt(3, quantity);

        ps.executeUpdate();

    } catch (SQLException e) {
        System.err.println(
            "Database error: " + e.getMessage());
    }
}</code></pre>
</div>

<div class="answer a3">
<h4>Retrieve Products</h4>
<pre><code>String sql =
    "SELECT id, name, price, quantity FROM products";

try (Connection con =
        DriverManager.getConnection(URL, USER, PASSWORD);
     PreparedStatement ps =
        con.prepareStatement(sql);
     ResultSet rs = ps.executeQuery()) {

    while (rs.next()) {
        System.out.println(
            rs.getInt("id") + " " +
            rs.getString("name") + " " +
            rs.getDouble("price") + " " +
            rs.getInt("quantity")
        );
    }

} catch (SQLException e) {
    System.err.println(
        "Unable to retrieve products: " +
        e.getMessage());
}</code></pre>
